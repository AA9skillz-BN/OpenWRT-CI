# C8-688 参考系统评估

2026-11-20 在用户提供的 C8-688 上，通过网页认证后的页面源码与 SSH 只读检查，
核对了 Mwrt 5.1.1165-24（Padavanonly Immortalwrt-mt798x-24.10-SNAPSHOT，
内核 6.6.133）。这里只记录实际见到的行为及本仓库的适配结论，不推断其完整构建参数。
未改动参考系统的配置、服务、分区或固件。

## 可借鉴项及实现边界

| 观察 | 对本仓库的价值 | 本次处理 |
| --- | --- | --- |
| 设备面板汇总模组、温控、网口、双系统信息，提供手机导航 | 降低排障时在多个插件间查找的成本 | 独立实现只读 `luci-app-c8-688-status`；沿用现有主题 |
| 显示物理网口链路、速率与 LAN/WAN 角色 | 能区分未插线、PHY 故障和接口配置问题 | 读取 sysfs 网桥关系和 netifd 逻辑接口，展示实际关联，不改角色 |
| 此机 `eth1` 的 GPY211B 链路为 2500 Mbit/s；蜂窝 DHCP 走 `eth1` | 核对 C8 板载模组 Ethernet 路径，与 USB 拨号分开诊断 | 状态页同时展示 Ethernet 与 USB，保持本仓库已有 PHY 地址修正 |
| 有线 WAN 使用 `lan4`，蜂窝独立 `cell/cellv6`；网关监控有防抖和事件日志去重 | 多上行切换可以更易用，恢复日志可更清楚 | 保留为后续独立适配项；本仓库默认四个外口为 LAN，不自动改变 |
| 升级可选择保留 Wi-Fi、风扇等具体项目，恢复端逐项校验 | 跨版本升级可减少整份旧配置带来的兼容问题 | 后续设计需适配本仓库 OTA、双槽、原子恢复及参数验证；本次不改升级事务 |
| LuCI 静态翻译缓存与请求并发调整；源码模板直接完成主题修改 | 减少不必要请求及启动后动态修改页面的窗口 | 本次页面采用一个 RPC 快照、10 秒轮询；不先行改变全局主题和 uhttpd 设置 |
| Wi-Fi MAC 修复限定机型，尊重已保存配置，不改 Factory 校准分区 | 与本仓库已采用的设备限定修复方向一致 | 保持现有 `c8-wifi-mac` 和受测的首启 Wi-Fi 生成器 |

新的状态页是独立代码，未复制参考固件的自定义控制器、主题或闭源组件。
只读 RPC 的 ACL 仅开放 `status`，没有文件读取通配授权、UCI 写入或执行命令权限。
它从原始数据中选取明确字段，不输出 IP/MAC、密码、SIM 标识或完整配置/日志。
CPU 温度与 PHY 温度分开；无 RPM 节点时不把 PWM 百分比称为实际转速。
USB 根集线器速度不会被当成模组速度；接口名称来自实际设备和 netifd，不固定为 `eth2`。
默认路由来自主路由表，策略路由、DNS、互联网及真实 LAN 转发仍需另行检查。
下一次启动选择和环境 CRC 不在本页的验证范围。

## 不直接采用的设置

- 参考系统安装 `kmod-mt_wifi 7.6.6.1`，出现 `ra0/rax0` 等厂商驱动网卡；本仓库
  使用官方源码的 mt76。不能把驱动、内核模块或 `.dat` 配置直接移入当前内核，
  也不能据此断言哪一套 Wi-Fi 吞吐或稳定性更好。本次没有无线或转发吞吐对比测试。
- 参考系统装有 TurboACC/MTK 组件，但实读 firewall 的软件与硬件 flow offload
  配置均为 `0`；TCP 算法为 `cubic`。包存在不等于功能正在生效，也不能由此证明
  硬件 NAT 或 BBR 带来性能收益。
- 参考风扇脚本写入 `thermal_zone0/mode=disabled`，实机读取也为 `disabled`。
  本仓库继续保留内核冷却映射和 CPU 未知/75℃全速保护，不以降低保护换取手动可控。
- 参考机有 zram，但快照时 swap 使用为 0。一次内存快照不足以证明需要调整本仓库
  内存参数或周期性清缓存。
- 多卡切换、自动判断网口对端及自动恢复涉及 GPIO、AT、探测报文和路由写入。
  本次没有调用这些操作；实现前需逐项验证硬件映射、现有拨号插件互斥及失败回滚。

`eth1` 2500 Mbit/s、模组 `3466:3301` USB 480 Mbit/s、独立 CPU/PHY 温度及 PWM。
这是后端读取验证，未把新包安装到参考系统，也未改变其页面。

回归使用真实 ucode，仅替换 sysfs/ubus I/O，覆盖无传感器、错误温度/PWM、
不可读路由、拒绝路由、非法网卡路径、其它机型和私有字段排除。
前端验证 0/未知区分、刷新失败的旧快照标识和导出禁止。
机型 Profile 同时要求安装包和最终 squashfs 内四个文件与源码逐字节一致。
完整固件构建、镜像验收和新页面的真机安装仍需后续获准进行。
