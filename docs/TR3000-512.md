# TR3000 512MB 固件构建与维护

## 适用设备与源码

- Cudy TR3000 v1，512MB 闪存硬改版，设备标识 `cudy,tr3000-v1`。
- 源码：<https://github.com/VIKINGYFY/immortalwrt>，分支 `owrt`。
- 仅适用于已验证的分区：UBI 起点 `0x5c0000`，长度 `0x1da40000`；页大小 2048 字节、擦除块 128KiB。
- 不适用于未经核对的原厂、256MB 或其他 U-Boot 分区布局。

## 文件位置

| 文件或目录 | 用途 |
|---|---|
| `.github/workflows/TR3000-512-VIKING-Standalone.yml` | 独立构建入口、依赖安装、编译、上传与发布 |

| `Scripts/TR3000-512/turboacc.sh` | 下载指定提交的 nftables TurboACC 插件 |
| `Scripts/TR3000-512/aurora.sh` | 下载 Aurora 主题及配置插件 |
| `Scripts/TR3000-512/configure.sh` | 应用配置、检查关键软件包、复制首次启动文件 |
| `Scripts/TR3000-512/verify-build.py` | 检查最终配置、镜像软件包清单及设备元数据 |

后续维护只修改 TR3000 专属文件，不改仓库原有公共代码。

## 默认功能与登录

- 后台地址：<http://192.168.6.1>，用户名 `root`；首次登录设置密码。
- Aurora 主题及 Aurora 配置插件，默认简体中文。
- LuCI 基础、防火墙、软件包管理、Aurora 配置、TurboACC、ttyd 均选择简体中文包；OpenClash 自带中文翻译。上游未翻译的文字、系统日志和终端命令输出可能仍是英文。
- ttyd Web 终端及中文管理入口：后台“系统 → 终端”，使用路由器系统账号登录。
- mt76 开源无线驱动、TurboACC 管理界面、软件及硬件 Flow Offloading、WED。
- OpenClash；Mihomo 内核与订阅需在刷机后另外下载、导入。
- F50 USB 网络驱动：RNDIS、CDC Ethernet、CDC NCM。

F50 启用 USB 网络共享并接入后，将实际出现的 USB 网卡配置成 DHCP 客户端，加入 WAN 防火墙区域。
F50 与 TR3000 的 LAN 网段不能相同。USB WAN 和 OpenClash 代理流量不保证能硬件卸载。

## 构建与下载

1. 进入 Actions，选择 `TR3000-512-VIKING-Standalone`。
2. 点击 Run workflow，选择包含最新配置的分支。
3. 成功后在 Releases 下载本型号的升级固件和 `sha256sums`。
4. Release Tag 以 `tr3000-512-` 开头；介绍来自专属模板，并追加源码提交与构建链接。

Release Tag 包含构建时间、运行编号和重跑编号，不与 AP3000M 共用 Tag，也不抢占 Latest 标记。
Release 附件仅包含 `sysupgrade.bin` 和对应的 `sha256sums`。成功时不上传 Artifact；失败时上传诊断日志 Artifact，保留 7 天。
下载依赖前检查 `make defconfig` 是否保留必需配置；发布前再次检查生成镜像的 manifest，确认中文包、ttyd、无线与 F50 驱动、OpenClash 依赖和 TurboACC 已装入镜像，并读取 sysupgrade 元数据核对设备标识。检查失败即停止发布。
失败诊断上传非隐藏的 `build.config`、编译日志，以及已生成的设备 manifest 和镜像元数据。

`Auto-Clean.yml` 现按型号分别保留最新 3 个已发布 Release，每天香港时间 05:21 自动执行；AP3000M 与 TR3000 独立计数。未知型号及草稿跳过，Git Tag 和 Actions 记录保留；手动运行默认只预览，勾选 APPLY 才执行删除。

## 升级与验证

使用名称包含 `cudy_tr3000-v1-squashfs-sysupgrade.bin` 的镜像。
升级前备份配置、核对 `sha256sums`，执行 `sysupgrade -T /tmp/实际固件文件名.bin`，通过后再升级。
首次跨源码升级建议不保留配置；不要用 `-F` 绕过尚未查明的检查错误。

首次启动脚本会设置 LAN 地址为 `192.168.6.1`，即使保留配置升级也可能覆盖旧地址。
刷入后检查 Wi-Fi、512MB 分区、TurboACC、OpenClash 和 F50 USB 上网。

## 后续修改

- 增减软件包：编辑 `Config/TR3000-512.txt`，必要时调整插件下载脚本。
- 修改默认地址和语言：编辑 `Files/TR3000-512/etc/uci-defaults/99-tr3000-local-settings`。
- 修改加速默认设置：编辑同目录的 `99-tr3000-flow-offload`。
- 修改发布介绍：编辑 `release-notes/TR3000-512.md`。
- 修改分区前必须重新核对实际机器布局，不能仅按闪存总容量推算。

原独立版已完成用户上机验证；拆分后的工作流仍需完成一次云端构建与发布验证。

## 编译缓存

启用 `CONFIG_DEVEL=y` 和 `CONFIG_CCACHE=y`，通过 `actions/cache` 保存 `.ccache` 和源码下载目录 `dl`。源码的 ccache 选项受 DEVEL 控制，缺少 DEVEL 时会被 `make defconfig` 移除。
ccache 容量上限为 2GiB；缓存键使用 TR3000 专属前缀、系统架构、源码提交、配置及脚本哈希和运行编号。
恢复时优先匹配同源码与配置，再回退到本产线已有缓存；缓存内容仍由 ccache 和下载校验机制检查。
每次成功编译后保存新缓存，即使随后的 Release 发布失败也可复用。
首次构建缓存为空，后续命中才能加速；未缓存 staging_dir 或 build_dir，工具链仍可能重新编译。
仓库原有 Cache-Clean 若删除所有缓存，也会清除本产线缓存，但不会影响固件正确性。
