# 在线升级设计与后续机型接入

用户维护偏好：后续编译和新增机型时，主动评估并优先复用当前在线升级能力。
当前实现覆盖 AP3000M 和 C8-688，尚未安装到 TR3000 或其他机型。
是否接入以及具体刷写方式，需要依据目标机型适配，不能仅替换设备名称。

### C8-688 适配

C8 的 CLI、ABI、配置、启动与定时脚本在 `Scripts/C8-688/ota/`，LuCI/RPC 在
`Scripts/C8-688/luci-app-c8-688-ota/`。渠道为 `C8-688-immortalwrt-master-`，
只接受该机型的 sysupgrade 附件，独立脚本附件为 `c8-688-ota` / `c8-688-ota-update.json`。
AP 与 C8 的模型、状态、配置和 ABI 分别维护，不能互相安装独立更新脚本。

C8 升级前检查当前板型、第二系统启动参数、p2/p8/p9 分区标签和有效启动环境，
下一次启动必须仍指向第二系统。继续调用 `sysupgrade -T` / `sysupgrade`，
由已有 C8 平台适配器限制写入 `kernel_2nd` / `rootfs_2nd`；不直接写块设备。

同一页面提供需确认的“切回第一系统”按钮：与 OTA、下载、自更新共用
`/var/lock/c8-system.lock`，只将现有 `boot_system` 改为 0，读回一致后重启。
环境配置或 CRC、板型、运行槽位不符时拒绝操作；不会复制或重建原厂固件。
运行状态和原厂系统是否完好仍需真机验证。

## 必须保留的行为

1. **渠道隔离。** 构建期写入设备版本标签；按机型和源码渠道查找 Release，过滤 draft 和
   prerelease，按发布时间选择目标，不把整个仓库的 latest 当作所有机型的最新版。
   页面启动下载/升级时固定标签，避免检查与刷写期间目标漂移。
2. **可信元数据与文件校验。** 元数据从 GitHub API 获取；镜像站只传输文件。
   下载前验证目标、文件名、大小和 SHA-256，下载后重新计算；发布 Artifact 转交后也核对校验和。
   缺少有效元数据或校验失败时，禁止刷写。
3. **机型升级检查。** AP 当前使用 `sysupgrade -T` 检查镜像，再执行升级。
   新机型必须适配其升级检查和写入入口；镜像类型、目标槽位、分区容量及保留配置位置不能沿用猜测值。
4. **配置和升级结果。** 提供保留/清空配置选项，默认保留；升级前备份配置。
   写入待验证标签，重启后核对实际运行标签并记录结果。该结果只说明版本是否切换成功，
   不证明网络、散热或所有功能正常。
5. **离线回退。** 下载时保存仓库、渠道、标签、文件名、大小和摘要。
   已下载镜像离线使用前重新核对这些记录、文件摘要和机型升级检查。
   缺少记录的旧镜像不能直接视为已认证文件。
6. **操作互斥。** 下载、升级和 CLI 自更新共用内核文件锁；后台操作提供状态及失败详情。
   LuCI RPC 检查退出状态，“已启动”不能当作“已完成”。
   自动检查和网页开关每次执行读取，允许用户关闭；不默认自动刷写固件。
7. **受控 CLI 自更新。** 整包固件包含工具；独立 `self-update` 只取当前渠道正式 Release 的
   CLI 与兼容元数据附件，不从 `main` 分支直接更新。验证 API 的大小/摘要、元数据中的标签、
   CLI 大小/摘要、固件兼容版本和依赖，再做 shell 语法检查。通过后备份原脚本，
   在同一文件系统原子替换，不执行下载代码来检查兼容性。
8. **固件兼容版本。** 兼容标记安装在固件的 `/usr/share` 中，CLI 自更新不修改该标记。
   变更 UCI/RPC/UI 契约或不兼容运行依赖时，维护者必须递增 ABI。
   摘要负责文件完整性，ABI 是经过审查的兼容声明，二者都不等于自动证明全部兼容性。
   旧固件缺少标记或版本不符时要求整包升级；旧脚本不会被远程自动修正。

## 新机型接入时需要确定的内容

- **设备与发布：** 机型标识、允许的源码渠道、Release 标签前缀、设备版本文件、镜像附件规则。
  BUILD_ONLY 标签可能没有远程 Release 或 Git tag，不能假定它能作为远程脚本来源。
- **刷写与存储：** 镜像格式、实际升级检查/写入入口、分区及槽位、镜像大小限制、下载空间、
  配置备份/恢复方式。A/B、UBI、eMMC 必须按设备处理，不宣称跨机型通用。
- **运行接口：** CLI、RPC、LuCI、UCI 和 init/cron 的名称及协议，必需命令/包、ABI、锁和状态文件。
  新增自动检查应保留开关，不将“在线升级能力”解释成无人确认的自动刷机。
- **发布附件：** 固件、实际配置、manifest、校验和、源码/feeds/插件及镜像证据；
  支持独立 CLI 更新时再加入 CLI 和兼容元数据。自更新只替换 CLI，不顺带更新 UI/RPC/配置。

接入时先复用稳定行为和测试，再决定是否抽取公共组件，避免一次扩散未验证的适配。
不因新增 OTA 更换设备源码、删除已有功能或放宽现有构建闸门。

## 验证与交付边界

- 行为测试覆盖渠道过滤、指定版本、损坏/缺失摘要、离线记录、互斥、后台错误、
  ABI/依赖拒绝以及自更新失败时保留旧脚本。
- 完整构建继续验证单设备配置、必需包、manifest、设备元数据、实际 FIT/DTB/squashfs。
  最终镜像核对脚本、兼容标记、执行权限、启动链接和本次构建标签。
- 先做配置预览，再完整 BUILD_ONLY；检查固件及发布附件，真实发布路径另行记录验证范围。
  构建/隔离测试通过不能替代真机上的刷写、保留配置、掉电恢复或网络验证。
