# C8-688 蜂窝界面与后台适配

用户选择采用参考系统同款 WEBUI、由本仓库维护 C8 后台。主入口为
**网络 → 蜂窝设置**，原 MT5700M 的全部页面保留在“兼容维护”下。
完整固件构建目前暂停；本改动尚未随新镜像发布、安装或完成硬件验收。

## 功能如何连接

| 页面/能力 | 实现与限制 |
| --- | --- |
| 概览、网络、信号、邻区 | 同款页面发送实际 AT 查询，无演示数据。模组不支持的命令返回失败。 |
| 拨号、APN、认证、拨号模式 | 原 APN 事务先持久化旧设置，写后回读，并同步拨号模式到 UCI；失败恢复。 |
| 网络制式、锁频、小区 | 经同一互斥传输执行，仅用户操作时写入；不能由页面存在推断运营商或模组支持。 |
| 短信中心、设置、终端 | 实际 AT；MT5700M 使用字面 `\\r` 的单帧 PDU，不追加 Ctrl-Z。发送必须收到独立 `+CMGS` 和最终 OK。长中文/emoji 分段继续可用“兼容维护 → Messages”。 |
| 三卡槽 | 顶部提供外置 1 正面、外置 2 反面、内置；显式确认后切换 GPIO/模组，回读不等于注册或联网成功。硬件映射仍待本仓库镜像上逐槽验收。 |
| 模组升级 | 同款页面的 FOTA 命令，仅用户显式操作时运行；不代替路由器系统 OTA，也未执行模组刷写验收。 |
| 新短信提醒 | 顶部单独配置企业微信 HTTPS 地址，默认关闭，仅发送新短信数量，不含正文。保留模组短信，不自动删除。失败或结果不明不自动重发。 |
| IPv4/IPv6/DNS 检查 | 显式发起、绑定实际上行设备的 HTTPS 探测，输出已脱敏；不冒充真实 LAN 客户端转发验证。 |
| 原流量、诊断及高级维护 | 原包页面和服务保留在兼容维护；不另建竞争串口读者。 |

## 认证、时序与失败处理

WEBUI 的 WebSocket 对象只作为协议兼容对象，由桥接脚本调用同源已登录 LuCI
的 ubus。路由器不开放新的 8765 AT 端口，HTTP/HTTPS LuCI 均走同源认证。
直接打开静态页、失效登录、无写权限均不能提交操作。rpcd 只允许 submit/result，
不能传入任意可执行路径；本地 Unix socket 仅 root 可访问。

单 worker 串行执行任务，并与原 manager、短信和温度查询共享 fd9 action 锁与
原生 transport 锁。请求 nonce 防重复；失去返回后不重放写命令，也不把迟到回复
配给下一条命令。队列超时尚未执行的任务作废，已执行结果短期保留在 RAM。
完整前端命令超时适配异步任务，短信收集明确处理完整 JSON 失败。

切卡事务先同步保存数字型回滚记录，失败恢复 GPIO、SCICHG、CFUN，并重新启用
SIM 热插拔检测；不承诺恢复切换前被人为关闭的 HVSST 状态。失败回读或进程被杀
时保留记录，普通 AT 拒绝冲突操作，后续 broker/manager 在同锁内先恢复。
记录损坏时不执行其中的文本；需人工检查。不会自动轮换卡槽。

保留现有 Ethernet `eth1` 接口、DNS、metric、IPv6 与防火墙；已有显式 USB
MT5700M 接口则保留 USB 管理路径。停止 Ethernet 监控服务不会关闭 WAN，
自动恢复只刷新已有 DHCP 接口，不执行 USB NDIS 切换。用户显式断开/重拨仍能
操作所选接口。首启只建立缺失的插件配置段，不覆盖已有 APN 或启用已禁用连接。
已有 USB 临时恢复措施仍按原机型文档记录，不迁移成所有设备的默认配置。

## 验证与交付边界

Linux `BUILD-CHECKS.yml` 的 `test_c8_cellular.py` 执行锁定源码的补丁幂等/漂移、
实际静态与运行包安装、真实 C 传输的 TCP/PTY/长短信回归、浏览器 PDU 帧、
认证桥接、短信错误处理、队列去重/超时、模拟三卡槽失败/恢复、APN 回滚和
配置保留。Node 还执行实际 bundle 的短信响应处理片段，未用相同错误假设重写它。

最终镜像闸门要求新运行时、菜单、ACL、init、启动链接、改写后的原后台及全部
前端资产与构建源码一致。包选择进入 Config 和 required_packages。
源码测试与安装配方检查不能替代 defconfig、完整镜像及硬件功能验收。

后续需在用户恢复构建后验收唯一 C8 镜像、实际 FIT/DTB 和 squashfs，再按授权
安装；三槽、模组 FOTA、通知投递及 Ethernet/USB 重启恢复分别记录实测结果。
现有 Release 和参考路由器均未被此次代码替换。
